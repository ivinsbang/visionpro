# Security reporting

This application is under development, with no deployed service or supported
production release.

Report suspected vulnerabilities privately to the repository owner through an
existing private contact channel. When GitHub private vulnerability reporting is
enabled, use the repository's Security tab. A dedicated reporting contact must be
published before external distribution.

Include the affected component, reproduction steps, expected and observed
behavior, and potential impact. Redact credentials and customer information.
Do not include working secrets or private account data in a public issue.

If credentials are accidentally committed, revoke or rotate them promptly;
deleting the file alone does not remove credentials from history.

Product-specific requirements are recorded in
[security and privacy](docs/security/README.md).
